# Internacionalização (i18n) — Viagens Mobile

## Idiomas
- `pt-BR` (padrão)
- `en`
- `es`

## Como adicionar tradução em uma funcionalidade nova

1. **Crie o namespace** (se ainda não existir), por exemplo `booking.json`, em:
   - `src/i18n/locales/pt-BR/booking.json`
   - `src/i18n/locales/en/booking.json`
   - `src/i18n/locales/es/booking.json`

2. **Registre** em `src/i18n/resources.ts` (import + entrada nos 3 idiomas).

3. **Adicione o nome** em `src/i18n/types.ts` → `I18N_NAMESPACES`.

4. **Na tela/componente:**
   ```tsx
   import { useTranslation } from 'react-i18next'

   function BookingScreen() {
     const { t } = useTranslation('booking')
     return <Text>{t('title')}</Text>
   }
   ```

5. **Datas e números:** use `formatAppDate` / `formatAppNumber` de `src/i18n/format.ts` em vez de `toLocaleDateString('pt-BR')`.

6. **Erros de API:** use códigos (`TRIP_NOT_FOUND`) em `errors.json`; traduza com `translateApiError(code)`.

## API
O app envia `Accept-Language` em todas as requisições. Ao mudar idioma no perfil, chama `PATCH /auth/me` com `{ locale }`.

## Namespaces atuais (mobile)
`common`, `tabs`, `auth`, `profile`, `utilities`, `trip`, `expenses`, `group`, `invite`, `tools`, `errors`

## Site (viagens-frontend)
Mesma convenção de namespaces em `src/i18n/locales/` com `vue-i18n`.
Namespaces iniciais: `common`, `nav`.
